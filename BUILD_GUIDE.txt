======================================================================
1. UEBERBLICK UND DATEIEN
======================================================================

Lokale Web-App: Flask + SQLite + Vanilla JS, kein Build-Step. Sie holt Unternehmen aus einer Datenquelle,
reichert sie an (Website-HTML, Bewertungstexte, Oeffnungsstatus), berechnet Signale und einen Score 0 bis 100 %,
speichert dauerhaft und zeigt sie in drei Tabellen (Neu, Alt, Exportiert). Aenderungen sind ueber ein Log mit
Undo/Redo umkehrbar.

Abhaengigkeiten (requirements.txt): flask>=3.0.0, requests>=2.31.0, openpyxl>=3.1.0. Python 3.9+ (zoneinfo).

Dateien:
  app.py             Flask-Routen (duenn, keine Logik)
  lead_logic.py      Datenquelle + Erkennung + Score. ENTHAELT ALLES GOOGLE-SPEZIFISCHE
  db.py              SQLite: Schema, Migration, Queries, Log/Undo
  exports.py         CSV, Excel, HubSpot-CSV
  templates/index.html
  static/app.js
  static/style.css
  leads.db           (gitignored, wird automatisch angelegt)
  .gitignore         leads.db, __pycache__/, *.pyc, .DS_Store
  README.md          Projektbeschreibung fuer GitHub + Schnellstart inkl. Google-Key-Einrichtung

Start: export GOOGLE_MAPS_API_KEY="..." ; python3 app.py   -> http://127.0.0.1:5050 (Port 5050, debug=False)

WICHTIG: Flask ohne Debug cached Templates. Nach HTML-Aenderungen Server neu starten. Alten Prozess vorher beenden:
lsof -ti :5050 | xargs kill -9

ADAPTER-VERTRAG (Ziel beim Umbau). Jeder Provider liefert Objekte in exakt diesem Format, danach ist alles gleich:

  RawPlace = {
    "id": str,               # stabil + eindeutig (mit Prefix, z. B. "osm:node/123")
    "name": str,
    "address": str,
    "phone": str,
    "website": str,
    "rating": float | None,
    "rating_count": int,
    "business_status": "OPERATIONAL" | "CLOSED_TEMPORARILY" | "CLOSED_PERMANENTLY" | "FUTURE_OPENING" | "",
    "open_now": bool | None,
    "opening_date": {"year": int, "month": int|None, "day": int|None} | None,
  }
  class Provider:
      max_radius_km: float | None                 # Google: 50
      geocode(region)  -> {"latitude":..,"longitude":..} | None
      search(category, region, count, center, radius_km) -> list[RawPlace]
      reviews(place_id) -> list[str]              # [] wenn nicht unterstuetzt

MAPPING Google -> RawPlace:
  id                                            -> id
  displayName.text (Default "unbekannt")        -> name
  formattedAddress                              -> address
  nationalPhoneNumber, sonst internationalPhoneNumber -> phone
  websiteUri                                    -> website
  rating                                        -> rating
  userRatingCount (oder 0)                      -> rating_count
  businessStatus                                -> business_status
  currentOpeningHours.openNow                   -> open_now
  openingDate {year, month, day}                -> opening_date

4. lead_logic.py: JEDE FUNKTION
======================================================================

now_cet_sortable() -> str
  datetime.now(CET).strftime("%Y-%m-%d %H:%M:%S"). Sortierbar, immer mit Uhrzeit.

geocode_region(api_key, region) -> dict | None            [Google-spezifisch]
  POST places:searchText, Body {"textQuery": region, "languageCode": "de"}, Feldmaske "places.location".
  HTTP != 200 -> RuntimeError("Places API Fehler {status}: {text[:300]}").
  Rueckgabe: places[0].location ({"latitude","longitude"}) oder None.
  Funktioniert fuer Staedte, Bezirke und PLZ (getestet: "Berlin", "Wien", "10115 Berlin").

search_places(api_key, query, max_results, location_bias=None) -> list[dict]   [Google-spezifisch]
  Feldmaske: places.id, places.displayName, places.formattedAddress, places.internationalPhoneNumber,
    places.nationalPhoneNumber, places.websiteUri, places.rating, places.userRatingCount, places.businessStatus,
    places.currentOpeningHours.openNow, places.openingDate, nextPageToken
  Body: {"textQuery": query, "languageCode": "de"}; bei Bias zusaetzlich
    {"locationBias": {"circle": {"center": {lat,lng}, "radius": Meter}}}; ab Seite 2 "pageToken".
  Schleife: while len(results) < max_results: sammeln, nextPageToken lesen, ohne Token break, sonst sleep(2).
  Rueckgabe: results[:max_results]. query ist f"{category} in {region}".
  Radius muss 0..50000 Meter sein, sonst HTTP 400 ("Radius must be in the range of [0, 50000]").
  locationBias ist nur eine Praeferenz, keine harte Grenze.

get_reviews(api_key, place_id) -> list[str]                [Google-spezifisch]
  GET places/{place_id}, Feldmaske "reviews"; bei Status != 200 -> [].
  Rueckgabe: reviews[].text.text (leere gefiltert). Google liefert maximal 5 Reviews (harte Grenze, keine Paginierung).

fetch_website_html(url) -> str
  Leere URL -> "". Sonst requests.get(url, timeout=10, headers={"User-Agent": "Mozilla/5.0"}).
  Status 200 -> resp.text.lower(); Status != 200 oder RequestException -> "". Nur die Startseite, keine Unterseiten.

detect_likely_new(rating_count, business_status) -> bool
  business_status == "OPERATIONAL" and rating_count < 5. Schaetzung, kein echtes Eroeffnungsdatum.

detect_opening_status(business_status, rating_count) -> str
  "FUTURE_OPENING" -> "Bald eröffnend"; trifft detect_likely_new zu -> "Neu eröffnet"; sonst "Etabliert".

format_opening_date(dict | None) -> str
  Ohne Jahr "". Jahr+Monat+Tag -> "TT.MM.JJJJ"; Jahr+Monat -> "MM.JJJJ"; nur Jahr -> "JJJJ".

detect_competitor(website, website_html, review_texts) -> str
  Haystack = website.lower() + website_html + alle Review-Texte lowercase, mit Leerzeichen verbunden.
  Fuer jedes System in Dict-Reihenfolge: kommt eine Signatur als Substring vor -> Systemname zurueck. Sonst "".
  Es werden nur Domains und Phrasen gematcht, keine blossen Markennamen im Fliesstext.

detect_pain_points(review_texts) -> list[str]
  Texte lowercase zusammenfuegen. Pro Label reicht der erste Regex-Treffer (re.search, dann break). Liste der Labels.

compute_score(competitor, likely_new) -> str               (Legacy-Ampel)
  kein Konkurrent und neu -> "Heiss"; kein Konkurrent -> "Mittel"; sonst "Niedrig".
  Wird im Feld "score" gespeichert, in der UI nicht angezeigt (nur im Export).

compute_icp_score(category, rating_count, competitor, chain_flag, pain_points, opening_status="Etabliert") -> (int, str)
  score  = CATEGORY_WEIGHTS.get(category, 15)
  score += 25  wenn competitor == ""
  score += 20  wenn rating_count >= 20, sonst 10 wenn rating_count >= 3
  score += 15  wenn chain_flag
  score += 10  wenn pain_points nicht leer
  score += OPENING_STATUS_BONUS[opening_status]
  score  = min(score, 100)
  tier   = "A" wenn score >= 65, "B" wenn score >= 40, sonst "C"
  Semantik: hoeher = besser, 100 % = perfekter Fit, sofort anrufen.

normalize_name_for_chain_check(name) -> str
  lowercase; Regex \b(gmbh|ug|e\.?k\.?|inh\.?|filiale|standort)\b entfernen; alle Ziffern entfernen;
  alles ausser a-z und Whitespace entfernen; Whitespace normalisieren.

flag_chains(leads) -> None   (in-place)
  Gruppiere nach normalisiertem Namen (leere Keys ignorieren). Gruppengroesse 3 bis 9 -> chain_flag = True.
  Nur innerhalb des aktuellen Batches (eine Suche mit einer Region).

enrich_place(api_key, place, region, category) -> dict     (Anfang Google-spezifisch)
  Liest die Google-Felder (Mapping Abschnitt 2), ruft get_reviews und (nur bei Website) fetch_website_html auf,
  berechnet alle Signale. Rueckgabe-Dict (DB-Format):
  place_id, name, address, phone, website, rating, rating_count, business_status, open_now,
  category_query, region_query, likely_new, opening_status, opening_date, competitor_system,
  pain_points ("Label1, Label2"), score, chain_flag=False, first_seen=now_cet_sortable(),
  icp_score=0, icp_tier="", status="Neu", notes="".

finalize_leads(leads) -> None   (in-place)
  ERST flag_chains(leads), DANN pro Lead compute_icp_score(...) (pain_points per split(", ") zurueck in Liste),
  icp_score/icp_tier setzen. Die Reihenfolge ist zwingend, weil der Score chain_flag braucht.

5. db.py: SCHEMA UND JEDE FUNKTION
======================================================================

DB_PATH = Path(__file__).parent / "leads.db"; row_factory = sqlite3.Row. Jede Funktion oeffnet und schliesst
ihre eigene Verbindung.

_now_cet(): wie now_cet_sortable. NIE SQLites datetime('now') nutzen (ist UTC).

Schema (exakt):
  leads(
    place_id TEXT PRIMARY KEY, name TEXT, address TEXT, phone TEXT, website TEXT,
    rating REAL, rating_count INTEGER, business_status TEXT, open_now INTEGER,
    category_query TEXT, region_query TEXT, likely_new INTEGER,
    opening_status TEXT, opening_date TEXT, competitor_system TEXT, pain_points TEXT, score TEXT,
    chain_flag INTEGER, first_seen TEXT, icp_score INTEGER, icp_tier TEXT,
    status TEXT DEFAULT 'Neu', notes TEXT DEFAULT '', hidden INTEGER DEFAULT 0, hidden_at TEXT)
  watched_searches(
    id INTEGER PRIMARY KEY AUTOINCREMENT, region TEXT, category TEXT, count INTEGER,
    radius_km REAL DEFAULT 0, created_at TEXT, UNIQUE(region, category))
  action_log(
    id INTEGER PRIMARY KEY AUTOINCREMENT, action_type TEXT, description TEXT, payload TEXT,
    undoable INTEGER DEFAULT 0, undone INTEGER DEFAULT 0, created_at TEXT)

init_db(): CREATE TABLE IF NOT EXISTS fuer alle drei Tabellen, danach _migrate_add_columns.

_migrate_add_columns(conn): liest PRAGMA table_info(leads) und ergaenzt fehlende Spalten per
  ALTER TABLE ADD COLUMN (icp_score, icp_tier, status, notes, opening_status, opening_date, hidden, hidden_at).
  Dasselbe fuer watched_searches.radius_km. Jede neue Spalte muss hier UND im CREATE TABLE stehen, sonst
  fehlt sie in bestehenden Datenbanken.

upsert_leads(leads) -> list[place_id]
  Pro Lead SELECT 1 WHERE place_id=?. Existiert er -> ueberspringen (NIE ueberschreiben, damit Status/Notizen
  nie verloren gehen). Sonst INSERT (Booleans zu int). Rueckgabe: nur die tatsaechlich neuen IDs.

remember_search(region, category, count, radius_km=0)
  INSERT ... ON CONFLICT(region, category) DO UPDATE SET count, radius_km.

get_watched_searches() -> list[dict]: region, category, count, radius_km.

get_all_leads(hot_only, region, category, tier, status, opening_status, include_hidden=False) -> list[dict]
  SELECT *; ohne include_hidden gilt AND (hidden IS NULL OR hidden = 0). Optionale Filter. Sortierung
  ORDER BY icp_score DESC, rating_count DESC.

get_lead(place_id) -> dict | None

update_lead(place_id, status=None, notes=None, hidden=None) -> bool
  Lead existiert nicht -> False. hidden=True setzt hidden=1, hidden_at=_now_cet(); hidden=False setzt hidden=0,
  hidden_at=NULL.

hide_leads(place_ids) -> list
  Selektiert die noch nicht ausgeblendeten IDs (IN (?,?,...)), merkt sich
  previous = [{"place_id":..,"previous":{"hidden":..,"hidden_at":..}}], setzt hidden=1, hidden_at=jetzt,
  gibt previous zurueck (Grundlage fuers Undo).

hide_leads_before(cutoff_date) -> list
  Selektiert IDs mit date(first_seen) <= date(?) und nicht ausgeblendet, ruft hide_leads(ids).

log_action(action_type, description, payload=None, undoable=False) -> int
  payload als JSON, created_at=_now_cet(). Rueckgabe: neue ID.

get_logs(limit=50): ORDER BY id DESC.

undo_log(log_id) -> dict | None
  None wenn Eintrag fehlt, nicht undoable oder schon undone. Sonst pro Payload-Item: aktuelle Werte derselben
  Felder lesen (= redo_payload), dann die previous-Werte per UPDATE leads SET feld=?,... WHERE place_id=?
  zurueckschreiben (Feldnamen stammen nur aus eigenem Code, nie aus User-Input). Danach undone=1.
  Rueckgabe: {"description", "count", "redo_payload"}.

6. app.py: JEDE ROUTE
======================================================================

get_api_key(): Header X-Api-Key hat Vorrang, sonst Env GOOGLE_MAPS_API_KEY.

GET /
  Rendert index.html mit categories=ICP_CATEGORIES und has_env_key.

POST /api/search   Body {region, category, count=20, radius_km=0}
  1. Kein Key -> 400. Region/Kategorie leer -> 400.
  2. radius_km = min(float(radius_km or 0), 50).
  3. regions = [r.strip() for r in region.split(",") if r.strip()].
  4. Pro Region (Radius gilt pro Ort): bei radius_km > 0 geocode_region, daraus
     location_bias = {"center": center, "radius": radius_km * 1000}. Dann
     search_places(f"{category} in {region}", count, bias), enrich_place je Treffer, finalize_leads,
     upsert_leads, remember_search(region, category, count, radius_km).
     RuntimeError wird pro Region in errors gesammelt, die Schleife laeuft weiter.
  5. Nur wenn ALLES fehlschlug (0 Treffer und 0 neue und Fehler) -> 502 {"error": "..."}.
  6. log_action("search", ...), nicht undoable.
  7. Antwort {found, new, new_place_ids[], errors[]}.

POST /api/sync
  Fuer jede watched_search dieselbe Pipeline mit gespeichertem count/radius_km; Fehler pro Suche in errors.
  Keine gemerkten Suchen -> 400. Log "sync". Antwort {synced_searches, new, new_place_ids[], errors[]}.
  Dauer gemessen: 7 Suchen = 58 s (ca. 8 s pro Suche), weil Reviews- und Website-Abrufe pro Treffer dominieren.

GET /api/leads
  Alle Leads inklusive ausgeblendeter (include_hidden=True). Die Einteilung Neu/Alt/Exportiert macht das Frontend.
  Query-Parameter hot_only, region, category, tier, status, opening_status existieren, das Frontend nutzt sie nicht.

PATCH /api/leads/<place_id>   Body {status?, notes?, hidden?}
  404 wenn unbekannt. Nach dem Update: hat sich hidden geaendert -> undoable Log "hide"/"unhide"
  (Payload = alter hidden/hidden_at). Hat sich status geaendert -> undoable Log "status_change".
  Notizen werden nicht geloggt.

POST /api/leads/hide-before   Body {date: "YYYY-MM-DD"}
  Blendet aus, loggt "bulk_hide" (undoable, Payload = alle betroffenen Leads). Antwort {hidden: n, log_id}.
  Leeres Datum -> 400.

GET /api/logs?limit=50: neueste zuerst.

POST /api/logs/<id>/undo
  db.undo_log. Bei None -> 400 mit deutscher Meldung. Sonst neuer Log "undo" mit payload=redo_payload und
  undoable=True. Undo vom Undo ist also Redo, die Kette ist unbegrenzt. Antwort {ok, count}.

GET /api/export?format=csv|xlsx|hubspot&hot_only=0
  rows = get_all_leads(hot_only) (nur nicht ausgeblendete). Diese werden per hide_leads ausgeblendet und als
  "export" geloggt (undoable). Danach send_file. Die Ausblendung passiert beim Abruf, auch wenn der Download
  nicht abgeschlossen wird. Es werden IMMER alle nicht ausgeblendeten Leads exportiert (Filter der UI wirken nicht).

======================================================================
12. TABELLEN-SWITCHING NEU / ALT / EXPORTIERT
======================================================================

Grundregel (renderAll), in dieser Prioritaet:
  1. hidden = 1                      -> Exportiert
  2. sonst ID in newOnlyIds          -> Neu
  3. sonst                           -> Alt
Die Tabellen werden bei jeder Aenderung komplett neu berechnet; es gibt kein manuelles Verschieben.

Uebergaenge:
  Suche/Sync fertig       newOnlyIds wird komplett durch die IDs der wirklich neuen Leads ersetzt. Alle vorherigen
                          "Neu"-Leads rutschen nach Alt. Findet der Lauf 0 neue Leads, ist Neu danach leer.
  "In HubSpot" (Neu/Alt)  PATCH hidden=true -> Exportiert. Log "hide", Toast.
  "Einblenden" (Exportiert) PATCH hidden=false -> zurueck nach Neu, wenn die ID noch in newOnlyIds steht (gleiche
                          Browser-Sitzung seit der letzten Suche), sonst nach Alt.
  Export CSV/Excel/HubSpot  Server blendet ALLE nicht ausgeblendeten Leads aus (unabhaengig von UI-Filtern);
                          nach 1,5 s Neuladen, dann liegen sie in Exportiert.
  "Bis Datum ausblenden"  alle nicht ausgeblendeten mit first_seen-Datum <= Stichtag -> Exportiert (auch aus Neu).
  Undo/Redo               loadLeads + loadLogs, danach ordnet die Grundregel neu ein.
  Seite neu laden         newOnlyIds leer -> Neu leer, alles Nicht-Ausgeblendete liegt in Alt.
  Status/Notiz aendern    kein Tabellenwechsel.
Spaltenfilter und Suchtexte je Tabelle bleiben beim Verschieben erhalten und gehen nur beim Neuladen verloren.

16. BEKANNTE GRENZEN, FEHLER UND RISIKEN
======================================================================

FEHLER IM CODE (geprueft, im Neubau direkt richtig bauen):
  1. Export ignoriert UI-Filter. exportAs schickt keine Filter. Wer in Alt nach "Treatwell" filtert und Export
     klickt, exportiert und blendet ALLE nicht ausgeblendeten Leads aus. Undo macht es rueckgaengig.
  2. Namens-Sortierung ist verkehrt herum: bei "absteigend" sortiert Name A bis Z (die Zahlen und die Zeit
     sortieren korrekt absteigend). Ursache: dir * a.localeCompare(b) bei dir = 1.
  3. Netzwerkfehler nicht abgefangen: geocode_region, search_places und get_reviews fangen requests-Fehler
     (Timeout, Verbindungsabbruch) nicht ab, app.py faengt nur RuntimeError. Ein Timeout fuehrt zu HTTP 500 fuer die
     GANZE Suche statt zu einem gesammelten Teilfehler; das Frontend zeigt "Netzwerkfehler: ...".
  4. Excel-Farben vertauscht: exports.py faerbt Tier A rot und C gruen, die UI zeigt A gruen und C rot.
  5. NICHT GEPRUEFT (nur vermutet): hide_leads baut ein IN (?,?,...) mit allen IDs; bei sehr vielen Leads koennte
     SQLites Grenze fuer Platzhalter ueberschritten werden. Bei ca. 40 Leads tritt das nicht auf.

DATENQUELLE (Google): maximal 5 Reviews (keine Paginierung); maximal 50 km Radius (sonst HTTP 400); kein
"Profil erstellt am"-Datum; kein Feld fuer "Jetzt buchen" (reservable gilt nur fuer Restaurants); Drittanbieter-
Bewertungen (z. B. Treatwell-Zahl im Panel) sind nicht per API erhaeltlich.

ERKENNUNG: Ein Buchungssystem wird nur erkannt, wenn die Domain im HTML der Startseite oder in den abrufbaren
Reviews steht. Unterseiten (z. B. /buchen) werden nicht geladen. "Neu eröffnet" ist eine Schaetzung.

DESIGN: Bestehende Leads werden nie neu bewertet. Undo eines aelteren Eintrags ueberschreibt spaetere Aenderungen
am selben Lead. newOnlyIds lebt nur im Browser. Test-Suchen fuellen die Produktiv-DB (fuer Tests eigene DB-Datei).

FALLSTRICKE: Templates werden ohne Debug gecacht (Server neu starten). Neue Spalten in beiden Tabellen migrieren.
Zeiten immer mit Uhrzeit und in Python erzeugen. leads.db und API-Keys nie committen (Repo kann oeffentlich sein).
